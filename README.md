# ربات فارسی شناسایی و دریافت رسانه

## وضعیت فعلی

این پروژه شامل هستهٔ تلگرام و آداپتورهای YouTube، Instagram (ویدیو + عکس/کاروسل) و ویدیوی Pin در Pinterest است: رابط فارسی، ثبت کاربر در SQLite، بررسی دامنه، انتخاب کیفیت، دریافت عکس و کاروسل تصویری Instagram، صف دانلود محدود با امکان لغو، و ارسال مستقیم فایل. اتصال‌ها best-effort و بدون ورود/کوکی هستند. **Pinterest فقط برای ویدیو Pin پیاده‌سازی شده است؛ Pinهای تصویری پشتیبانی نمی‌شوند. عکس و کاروسل تصویری Instagram از مسیر API عمومی وب Instagram و حداکثر ۱۰ تصویر در هر کاروسل دریافت می‌شود.**

فقط محتوایی را ارسال کنید که اجازهٔ دریافت و استفاده از آن را دارید. ربات به حساب‌های خصوصی، لینک‌های نیازمند ورود یا دسترسی‌های محدودشده دسترسی پیدا نمی‌کند.

## امکانات

- شناسایی خودکار پلتفرم از لینک HTTPS (شامل زیردامنه‌های رسمی مثل `m.youtube.com` یا `fa.pinterest.com`)
- انتخاب کیفیت ویدیو (تا 1080p در صورت موجودیت) و MP3 برای YouTube
- دریافت عکس تک‌ویدیویی و کاروسل‌های تصویری Instagram (حداکثر ۱۰ تصویر، سقف مجموع `MAX_CAROUSEL_MB`)
- صف دانلود محدود (حداکثر یک درخواست در صف/در حال اجرا برای هر کاربر) با نمایش موقعیت در صف
- نمایش پیشرفت دانلود (درصد، سرعت، زمان تقریبی) و **دکمهٔ لغو** تا پیش از پایان پردازش
- ثبت کامل رویدادهای دانلود در SQLite و داشبورد ادمین (آمار کلی، ۲۴ ساعت اخیر با تفکیک پلتفرم، وضعیت زندهٔ صف، بلاک/رفع بلاک کاربر)
- مسدودسازی کاربر در تمام مسیرها (میان‌افزار اختصاصی با کش کوتاه‌مدت)
- محدودیت نرخ درخواست (۶ رویداد در ۶۰ ثانیه؛ مدیران مستثنا) و سقف حجم فایل قابل تنظیم (پیش‌فرض و سقف مؤثر: ۴۹ مگابایت؛ مقادیر بیشتر در `.env` به‌صورت خودکار به این سقف محدود می‌شوند)
- escape خودکار عنوان‌های رسانه (متن‌ها با parse mode HTML ارسال می‌شوند و عنوان‌های حاوی `&`، `<` یا `>` پیام‌ها را نمی‌شکنند)
- پاک‌سازی خودکار سوابق دانلود قدیمی‌تر از `HISTORY_RETENTION_DAYS`

## نیازمندی‌ها

- Python 3.12 یا بالاتر
- توکن ربات از BotFather
- وابستگی‌های `requirements.txt` (و FFmpeg برای تبدیل MP3)

## اجرای محلی

۱. یک محیط مجازی بسازید و وابستگی‌ها را نصب کنید:

```bash
python -m venv .venv
source .venv/bin/activate  # در Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

۲. `.env.example` را به `.env` کپی کنید و `BOT_TOKEN` را تنظیم کنید. شناسه‌های عددی مدیران را در صورت نیاز با کاما جدا کنید.

۳. اجرا:

```bash
python main.py
```

پوشهٔ `data/` و پایگاه SQLite هنگام راه‌اندازی ساخته می‌شود. فایل `.env` را هرگز وارد Git نکنید.

## استقرار روی Railway / Back4App (کانتینر)

- هر دو سرویس از `Dockerfile` موجود build می‌کنند؛ تنظیمات `docker-compose.yml` (read-only، cap_drop و غیره) مخصوص اجرای مستقیم Compose است و روی این پلتفرم‌ها اعمال نمی‌شود.
- متغیر `BOT_TOKEN` (و در صورت نیاز `ADMIN_IDS`) را در پنل پلتفرم تنظیم کنید؛ نیازی به باز کردن پورت نیست (ربات polling است).
- پایگاه SQLite روی دیسک کانتینر ذخیره می‌شود؛ برای ماندگاری بین دیپلوی‌ها در Railway یک Volume روی `/app/data` سوار کنید (`DATABASE_URL=sqlite+aiosqlite:////app/data/bot.sqlite3`).
- **محدودیت مهم IP دیتاسنتر:** YouTube معمولاً استخراج ناشناس از IP مراکز داده را با bot-check مسدود می‌کند و API عمومی Instagram نیز در برابر درخواست‌های زیاد محدود می‌شود؛ ربات در این حالت پیام خطای شفاف نشان می‌دهد اما دانلود آن پلتفرم کار نخواهد کرد.

## آزمون‌ها

```bash
python -m pytest -q
```

این آزمون‌ها اعتبارسنجی URL، منطق امنیتی، صف، ثبت دیتابیس، فیلتر کیفیت، escape عنوان‌ها و مسیر دریافت عکس/کاروسل را می‌سنجند؛ اتصال واقعی به تلگرام یا استخراج رسانهٔ زنده را اثبات نمی‌کنند.

## محدودیت امنیتی فعلی

اعتبارسنجی لینک نحوی و مبتنی بر دامنه است و DNS preflight انجام می‌دهد؛ آدرس‌های CDN تصاویر Instagram به دامنه‌های رسمی (`cdninstagram.com`، `fbcdn.net`) محدود و از نظر IP عمومی بررسی می‌شوند؛ اما DNS rebinding و ریدایرکت‌های داخلی yt-dlp توسط هیچ دیوار آتش خروجی کنترل نمی‌شوند. جزئیات و پیش‌نیازهای انتشار عمومی را در `SECURITY_REVIEW.md` و `QA_REPORT.md` بخوانید.
